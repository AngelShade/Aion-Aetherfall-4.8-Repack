# Shared speech bubble styles — Aion 4.8 NA x64

Open the chat context menu and hover **Chat Bubble**, beside Font Size and Emotes. Choose Classic, Wings, Crystal, Cloud, or Paws. Exactly one style has a native checkmark; the active row is greyed and cannot be toggled off. Selecting another style immediately unchecks and enables the other rows. One style belongs to each character and is saved by the server. Normal chat and shouts carry that character's choice to other players using the updated game client. The original Tab Options layout is restored.

Wings uses gold wing flourishes and scrollwork; Crystal has angular amber facets and a jagged tail; Cloud has scalloped lobes and three thought dots. They use separate generated artwork and different minimum dimensions/padding. Paws keeps the original working paw frame. NPC thoughts, whispers, shops, and pet bubbles retain their normal behavior. Classic follows the native appearance of the current chat channel. Source artwork and exact prompts are in `assets/prompts.md`.

The client negotiates the packet extension automatically when the native game socket is ready and immediately when opening the menu. It uses the actual SendChat transport guard at Game.dll RVAs 0x133bb30/0x133bb38; the previous 0x13122f0 check was the g_gameReplay CVar and incorrectly blocked ordinary play with replay=0. Selection works before the client knows its character ID. The private server acknowledgement supplies that ID and saved choice; leaving the world clears cached identities. Each incoming normal/shout packet contains the sender's saved choice. Metadata and acknowledgements are consumed before ordinary chat display. Clients without the extension receive ordinary names; distribute the same updated client patch to everyone who should see the styles.

The native menu hooks are Game.dll RVAs 0x6736b0 (popup construction), 0x535e70 (popup command dispatch), and 0x5365b0 (refresh cached models before native copying/rendering). The popup hook updates the model and live widgets and consumes only the five speech commands. Message, skin, and update hooks are 0x73480, 0x4a2a83, and 0x4a0780. Artwork replacement at 0x4a2b18 resolves a custom registry resource before native SetRectangle/Draw. Stock definitions remain intact. Custom eleven-part definitions are added to Data/ui/ui.pak and the active English override; three alpha DDS textures are added to Textures/ui/ui.pak. The construction hook receives the parent item held in RDI. Existing native menu commands continue through their original handler.

`build_package.py` builds a fresh installation from the exact supported pre-speech Game.dll. `stage_menu_revision.py` revises the earlier installed speech patch from its verified original backup. It validates every currently recorded file, all original sources, and archive entries unrelated to Chat Options, then rebuilds the installed DLL and graphics/cursor restore baselines. Existing imports and patches are retained, with all import destinations writable for the Windows loader. Graphics/cursor tracking and the speech removal receipt are updated together. Launcher guards remain enabled.

After exiting Aion normally, `apply_menu_revision.ps1 -PreparedPath output/speech-bubbles/artwork-fix` installs the exact verified targets with a recovery backup and rollback on failure. It rejects later changes and refuses to replace a running client's DLLs. `restore.ps1` can remove the complete speech patch using the revised original receipt, restoring the prior graphics/cursor files and records together.

The checks execute all seven generated hooks in isolated memory and exercise the real extension against native-shaped menu/network fixtures. They execute the client's native event dispatcher at 0x4adeb0 with its real popup OnCommand virtual slot, then assert exclusive checks and enabled states on both cached models and visible siblings. The send regression executes the actual client SendChat packet builder, intercepting transport before encryption and checking packet framing and UTF-16 command bodies with replay=0. Native checkbox items use type 3, checked state at item+0x1a0, and enabled state at item+0x19c. Tests also cover automatic synchronization, independent character styles, reconnect/reset, hidden metadata, malformed names, and unchanged native menus. Test configuration exists only in a separate test DLL. Production exports a small read-only diagnostic counter array for confirming click, acknowledgement, and rendering paths without logging chat text. Launcher checks use an isolated fixture and exercise both composed restore baselines.

Server persistence uses settings_type=-3 in the existing player_settings table. PlayerSettingsDAO, PlayerSettings, AionConnection, SM_MESSAGE, and the Speechbubble command are deployed together. The existing Java check covers actual packet serialization, negotiated/unmodified client compatibility, and persisted settings in an automatically removed disposable schema.
