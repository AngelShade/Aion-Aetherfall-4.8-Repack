# Market quantities and batch deposits

Always Max is shared by Transfer Item and Register Sale and stored per account in `central_market_preferences`. Accounts default to off. Enabling it fills the open dialog and defaults future transfer/sale dialogs to their maximum quantity; sale quantities still respect the item registration limit. Buying keeps its existing default. Players can manually change the quantity and must still confirm each action.

Saving uses the authenticated market action endpoint, the account connection guard, strict boolean input, a database transaction and the existing request receipt mechanism. Repeated requests do not overwrite the setting twice. Failed saves keep the dialog open and recover the authoritative checkbox state before allowing another confirmation.

Transfer Market Warehouse is shown in the existing framed selection panel only for a non-empty selection from Inventory, Character Warehouse or Account Warehouse when every stack is eligible, unreserved and fits the remaining combined market volume. Preview eligibility matches the authoritative checks for equipped, bound, timed and pending-retune items and eligible item templates. The existing all-or-nothing batch transfer revalidates everything on confirmation. Selection and the button clear after a successful batch. Native item icons are loaded only as rows enter the confirmation viewport, six at a time.

Deployment uses a narrow transformation of the installed service class, adds one helper, installs the schema and three frontend assets, and backs up replaced files. Other installed methods, synthetic helpers, class constants, JAR entries, client files, configuration and static data remain preserved. Installed snapshot return hooks execute after the original database connection is closed; source snapshots read the preference through their current connection.

Validation: 194 checks against an isolated cloned test schema with JVM verification enabled; production HTML/CSS/JS checked with Aion 4.8 NA Awesomium at 1024x740 and 1920x1052 using 240 stacks per storage. Checks cover saved/reloaded defaults in both dialogs, failed-save recovery, all three source storages, invalid-item deselection/reselection, combined and exact-fit volume, batch completion, native item icons/tooltips, market browsing and Cash Shop regressions. Fixture actions never touch live players or inventories. Browser timings exclude the game GPU upload path.
